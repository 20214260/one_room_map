# 4인 협업 · 7일 실행 계획

## 오늘 사용할 수 있는 범위

샘플 6개로 비회원 탐색, 예산/옵션 필터, 검색/정렬, 상세, 2개 비교, 규칙 요약까지 작동합니다. 소셜/이메일 계정은 UI·입력 검증·HTTP 연결부까지이며 실제 인증 서버는 없습니다. 지도 키가 없으면 샘플 위치 모식도를 표시합니다. AI는 백엔드 연결 전 규칙 요약입니다.

`src/contracts/schemas.ts`, `src/domain`, `src/services/gateway.ts`, 전역 스타일 토큰은 공유 경계입니다. 이 파일을 바꿀 때 양쪽 담당자에게 PR 리뷰를 받으세요. 기능 폴더끼리 서로 데이터를 가져오지 않고 계약과 공통 컴포넌트를 통해 연결합니다. WebMCP와 분석 이벤트는 선택적인 어댑터라 제품 로직에 영향을 주지 않습니다.

전역 스타일은 `app/globals.css`가 한 번 가져옵니다. 병렬 UI 작업부터는 각 feature에서 CSS module을 추가하고 해당 컴포넌트에서 import하여 전역 파일 동시 편집을 줄이세요. 공통 토큰 변경과 화면별 스타일 변경을 하나의 PR에 섞지 않습니다.

## 브랜치와 PR

`main`은 시연 가능 상태 유지. `feat/explore-filters`, `feat/compare-ai`, `feat/auth-api`, `feat/listing-data`처럼 기능 단위로 작업합니다. 하루에 1번 이상 작은 PR을 합치고, API 변경은 DTO·문서·mock·테스트를 같은 PR에서 바꿉니다. 각 작업 시작 전 `git pull`, 공통 파일 충돌은 파일 담당자와 의미를 확인하고 해결합니다.

PR 체크: 목적, 요구사항 ID, 화면/응답 변화, 관련 스크린샷, `pnpm typecheck`, `pnpm test`, `pnpm build`, 알려진 제한. 환경변수 실제 값이나 비밀번호는 PR 본문/로그에 넣지 않습니다. `.github`의 이슈·PR 템플릿과 CI를 활용하세요.

## 시연 시나리오

1. 조건에서 월세 35만원, 관리비 5만원, 세탁기를 선택합니다.
2. 조건 칩 수정·삭제와 '내 조건만'을 확인합니다. 후문 지도 영역을 선택했다가 전체로 돌아옵니다.
3. 월 부담액 낮은순으로 정렬한 뒤 2개 매물을 선택합니다. 세 번째 선택은 차단됩니다.
4. 비교 화면에서 월 부담액, 면적, 도보 거리, 엘리베이터를 확인합니다. 값이 없는 방의 관리비는 추정되지 않습니다.
5. 선호를 입력해 비교 요약을 요청합니다. 현재는 '규칙 기반' 표시, 샘플 및 자연어 미반영 제한을 확인합니다.
6. 로그인 화면에서 비회원 복귀와 입력 오류를 확인합니다. 실제 사용자 계정은 생성되지 않습니다.

## 관측 이벤트

`src/services/analytics.ts`는 `sunroom:analytics` 브라우저 이벤트를 발행합니다. 이름은 상세 조회, 비교 진입/표시 완료, AI/규칙 요약, 로그인 성공이며 ID와 시각만 포함합니다. 아직 외부 수집 서버/영구 저장은 연결하지 않았습니다. 분석 담당자는 해당 어댑터에 전송을 구현하되 이메일·비밀번호·자연어 선호를 운영 로그에 넣지 않습니다.
