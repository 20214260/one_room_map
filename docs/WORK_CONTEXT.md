# 순룸 작업 맥락 · 다음 작업에서 먼저 읽기

## 사용자가 확정한 방향

순천대 인근 매물은 지도 검색 API만으로 충분하지 않아 집주인이 직접 등록한다. 가입 시 방 찾는 사용자와 집주인을 나누고, 집주인만 매물을 등록/관리한다. 지도 핀·사진·세부 정보·최소 입력 기반 설명 초안을 제공하며 최종 저장 전 본인이 수정한다. 기존 탐색·필터·비교·추천과 디자인은 유지한다. 백엔드가 없어도 양쪽 임시 로그인으로 흐름을 확인할 수 있어야 한다. BE 팀원이 연결하기 쉽도록 계약과 화면을 분리한다.

## 기준과 이번 변경

제공 원본: sunroom-source.zip, archive SHA 1e1abad376c0eb3c39d97887004bdac120cbfd0f. 사용자는 main 공통 변경이 모든 브랜치에 있고 팀원 매물 제출 브랜치만 추가 갱신됐다고 설명했다. 원격 Git 브랜치를 직접 조사/병합하지 않았고 ZIP의 실제 구현을 기준으로 작업했다.

기존 RoomSubmission, api.submitRoom/api.inquire를 확장했다. 새 역할·집주인 화면·사진·지도 클릭·초안 검토·매물 상태·문의함·체험 저장을 추가했다. 상세 변경은 LANDLORD_HANDOFF.md, 파일 목록은 CHANGED_FILES.md. 원본 유저플로우/기능명세 문서가 ZIP 밖에 있었다면 그 원문까지 복원했다고 주장하지 않는다.

## 유지할 원칙

- 기존 화면/데이터/비교 계산을 불필요하게 재작성하지 않는다.
- 금액은 원 정수, UI만 만원. 0과 미상(null), 옵션 false와 미상을 구별한다.
- AI가 미입력 사실을 만들어 넣지 않는다. 현재 초안은 rules이며 팀원 AI 연결 완료가 아니다.
- 공개 응답에 연락처를 넣지 않는다. 운영 권한은 서버 세션/소유권 검사로 보장한다.
- 실제 인증/지도/AI 검증 전 완료했다고 표시하지 않는다.

## 남은 실제 연동

추가 기능: 직접 등록한 매물에서 사용자→집주인 채팅, `/chats` 대화함, 읽지 않은 수, 방문 시간 제안·수락/거절, 신고·차단을 mock과 Gateway/HTTP 계약으로 추가했다. 샘플 매물에는 채팅 진입점을 노출하지 않는다. 기존 중계 문의 API와 문의함은 유지한다. 서버가 구현할 경로·응답·권한·매물 상태별 정책은 `docs/CHAT_HANDOFF.md` 참조. 실시간 전송은 아직 없고 화면이 12초 간격으로 갱신한다.

서버 role·소유권 검사, 운영 세션/OAuth 역할 온보딩, 매물 DB·검수, 이미지 업로드/정리, AI 초안, 문의 중계·답장 API, 실지도 키/주소 검증. 새 UI 실제 클릭 및 모바일 시각 검증은 실행 환경의 브라우저 제한으로 미완료. 구현 테스트/빌드는 통과했다. 원격 commit/push/merge/deploy는 하지 않았다.

다음 대화에서는 이 문서와 현재 코드/브랜치 상태를 함께 확인한다. 채팅 기억만으로 이전 작업 상태를 단정하지 않는다.
