# 순룸 설계: 요구사항 · 기술 구성 · 역할 분담

SCNU OSS · AI 해커톤 (고급 교육) 출품작. 서비스 주소 https://a7.scnuoss.net (팀 a7)

## 1. 문제 정의

순천대학교 학생이 자취방을 구할 때
- 월세만 보고 관리비·보증금까지 합친 **실제 한 달 비용**을 비교하기 어렵고
- 학교 근처 원룸은 지도·부동산 앱에 잘 올라오지 않으며 (집주인 개인 게시판·전단 위주)
- 매물 정보가 흩어져 있어 조건에 맞는 방을 **나란히 비교**하기 어렵다.

순룸은 **집주인이 직접 올린 순천대 인근 매물**을 예산·생활 조건으로 걸러 보고, 두 방을 비교하고, AI가 확인된 정보만으로 차이를 설명해 주는 서비스다. 집주인은 **소유 인증을 거친 뒤** 매물을 등록한다.

### 비기능 요구사항

| 구분 | 요구사항 | 구현 |
| --- | --- | --- |
| 정확성 | AI 가 없는 사실을 만들지 않음 | 모델 답변의 숫자·옵션을 DB 값과 대조, 불일치·실패 시 규칙 기반 결과로 대체 |
| 가용성 | AI·외부 서비스 장애에도 서비스 동작 | Gemini 실패 → 규칙 기반 요약, 카카오 키 없음 → 목록 사용 가능 |
| 안정성 | 서버 재시작·앱 오류 후 자동 복구 | Supervisor 자동 재시작, `@reboot` cron |
| 보안 | 비밀키·개인정보 비노출 | 키는 서버 `.env`(권한 600)만, 세션 HttpOnly 쿠키 + CSRF, 공개 응답에 연락처 제외, 인증 서류 비공개 보관 |
| 권한 | 화면이 아닌 서버에서 권한 검사 | 미승인 집주인 매물 API 403, 관리자 API 는 `ADMIN_EMAILS` 만 |
| 협업 | 백엔드 없이도 화면 개발 가능 | `mock` 모드 (브라우저 임시 데이터) |

## 3. 기술 구성

```text
                         https://a7.scnuoss.net (nginx, 강사 서버)
                    ┌───────────────┴────────────────┐
         정적 파일 (~/html)                   /api/* → 127.0.0.1:3107
   Next.js(vinext) 정적 빌드                FastAPI (Supervisor 관리)
   React 19 · Tailwind · shadcn              ├ 인증: 세션 쿠키 + CSRF, 카카오·구글 OAuth
   Kakao Maps JS SDK (브라우저)              ├ 매물·채팅·문의·집주인 인증·관리자 심사
            │                                ├ AI: Google Gemini (추천·설명 초안)
            └──── fetch /api/v1 ─────────────┤     └ 근거 검증 → 실패 시 규칙 기반
                                             └ SQLAlchemy ─→ Supabase PostgreSQL
                                                              Supabase Storage (사진)
```

| 계층 | 기술 | 이유 |
| --- | --- | --- |
| 프론트 | Next.js 16 (vinext on Vite 8), React 19, TypeScript, Tailwind 4, shadcn/ui, zod | 컴포넌트 재사용, 계약(zod 스키마)으로 API 형식 고정 |
| 지도 | Kakao Maps JavaScript API | 국내 주소·지도 정확도 |
| 백엔드 | FastAPI, Pydantic, SQLAlchemy, uvicorn | 빠른 API 개발, 자동 문서(/docs), 입력 검증 |
| DB·저장소 | Supabase PostgreSQL, Supabase Storage | 관리형 DB, 무료 티어 |
| AI | Google Gemini API (`gemini-3.8-flash`, 예비 `gemini-3.5-flash`) | 한국어 품질, JSON 스키마 출력, PDF·이미지 입력 지원 |
| 인증 | 자체 세션(HttpOnly 쿠키, scrypt 해시), 카카오·구글 OAuth(PKCE) | 토큰을 브라우저 저장소에 두지 않음 |
| 배포 | nginx(강사 서버) + Supervisor + cron, `scripts/deploy.sh` | 대회 서버 규칙(사용자 권한, systemd 변경 금지) |
| 협업·품질 | GitHub 브랜치·PR, GitHub Actions(타입 검사·테스트·빌드), pytest 282개 | 파트별 병렬 작업, 회귀 방지 |

### 코드 구조와 계약

- 화면은 `src/services/gateway.ts` 만 호출 → `mock` / `http` 모드 전환
- 데이터 형식은 `src/contracts/*.ts` (zod) 와 백엔드 Pydantic 모델이 같은 규칙
- 검색·필터 로직은 프론트 `src/domain/rooms.ts` 와 백엔드 `app/search.py` 가 같은 결과 (fixture 로 검증)
- 상세: [API 계약](API_CONTRACT.md), [집주인](LANDLORD_HANDOFF.md), [채팅](CHAT_HANDOFF.md), [집주인 인증](OWNER_VERIFICATION_HANDOFF.md), [배포](DEPLOY.md)

### AI 기능 설계

| 기능 | 입력 | 출력 | 안전장치 |
| --- | --- | --- | --- |
| 비교 추천 | 매물 ID 2개 (서버가 DB 에서 다시 읽음) + 조건 + 선호 문장 | 요약, 방별 장점·아쉬운 점 (근거 항목 표시) | 숫자를 단위별로 DB 값·두 방 차이와 대조, 모르는 옵션 단정 금지, 선호 문장은 지시로 따르지 않음 |
| 설명 초안 | 입력한 매물 정보 + 기존 게시글(연락처는 가려서 전송) | 소개글, 게시글에 적힌 금액 제안 | 입력에 없는 채광·거리·면적 등 추정 표현·연락처 포함 시 거절, 금액 제안은 게시글에 있는 값만 |
| 서류 심사 보조 (예정) | 신청 이름·주소 + 등기 서류 | 추출값, 일치·불일치·확인 필요 | 승인 권한 없음 (관리자가 결정), 결과는 참고용 |
